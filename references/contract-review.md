# 智能合同审核流程

## 审核前收集

首先只检查当前任务/当前线程中用户是否明确说明本次合同审核立场。禁止读取、搜索或使用 WorkBuddy/宿主全局记忆、长期记忆、用户画像、其他任务、其他线程、旧合同、旧审核报告、示例、评测、交接文档、测试记录或日志推断甲乙方，也不得据此选择合同文件或补充审核要求。如果当前任务没有说明，必须调用宿主原生单选或表单工具询问“您是甲方还是乙方？”，并核对 `optionManifest` 中两个选项都已完整显示；少一项时不得接受答案。选择器容量不足时改用可完整显示编号列表的原生表单或输入组件。只有确认当前会话没有任何兼容原生组件时才显示：

```text
请选择合同审核立场：
1. 甲方
2. 乙方
请直接回复编号或选项文字。
```

在用户回答前，不上传文件、不创建访问记录，也不发起审核。

取得立场后，再确认以下内容：

- 当前任务中用户提供的合同文件本地路径
- 是否启用思考模式

文档支持 PDF、DOC、DOCX，每次一份；图片支持 JPG、JPEG、PNG，最多十张；单个文件不超过 10MB。合同文档和图片分开提交。

## 发起审核

```json
{
  "filePaths":["/绝对路径/合同.docx"],
  "contractualStanding":1,
  "thinking":false
}
```

传给 `contract-review`。`contractualStanding=1` 表示甲方，`2` 表示乙方。该值必须来自当前任务中用户明确陈述或亲自选择，不得来自任何跨任务记忆。若未传有效立场，脚本返回 `stage=needs_input` 和甲方、乙方两个选项，不会读取或上传合同文件。

脚本依次上传文件、创建访问记录并调用 `/contract/audit`。该接口采用阻塞返回，成功响应已经包含 `recordId` 和完整 `riskPoints`，正常流程直接生成报告。

## 恢复异常任务

如果错误对象的 `details.canResume=true`，保存其中与当前任务明确对应的 `sessionId`，调用：

```json
{"sessionId":"任务编号"}
```

传给 `resume`。不得从全局记忆或其他任务猜测、搜索、加载 `sessionId`。恢复流程只查询一次 `/contract/getAuditDetail/{pvId}`，不会定时轮询。

## 展示结果

按高、中、低风险组织输出，每个重点风险包含：

- 风险条款
- 风险等级
- 风险说明
- 修改建议
- 建议替换文本

最后原样输出 `links[0].markdown`，固定显示为 `[合同审核报告](链接地址)`。最终风险总结、修改建议和法律依据只能来自审核报告及报告中已经列出的法规和依据；报告生成后不得搜索网页、查询法律数据库或补充报告外的内容。不得自动打开、预览或导航到报告页面；用户主动点击后自行决定是否下载审核报告、合同原件批注版或修订版，不直接把下载接口作为最终入口。
